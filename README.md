# RISC-V processor comparison: Hazard3, Ibex, VeeR EL2

A two-person student project at BITS Pilani (Dwiti Suchak, Ayush), supervised by Prof. Govind Prasad.

The project compares three open RISC-V cores on the same benchmarks, in three settings:

1. **FPGA**: a PYNQ board (Zynq-7000) with Vivado.
2. **ASIC, SKY130**: RTL-to-GDS with LibreLane, including an I/O pad ring.
3. **ASIC, SCL 180 nm**: the same RTL and the same flow steps, including I/O pads.

Area, timing and power are compared wherever it's feasible. Any core that can't go through a
stage gets a note in `docs/LIMITATIONS.md` instead of being dropped.

The rules every run follows are in **`CLAUDE.md`**: the ISA, configs, one binary per benchmark,
the two hardening scopes, clock targets and number integrity. Read it before changing anything.

| Core | Upstream | HDL | Pinned commit |

| Hazard3 | github.com/Wren6991/Hazard3 | Verilog | 8af9929 (v1.1.1) |

All software is built for `rv32imc_zicsr`. Each core's exact configuration and pipeline depth,

## Clone

The cores and two benchmark suites are git submodules. Clone with them:

```sh
git clone --recurse-submodules https://github.com/dwiti-25/processor-compare.git
cd processor-compare
```

If you already cloned without them:

```sh
git submodule update --init --recursive
```

| Submodule | Path |
|---|---|
| Hazard3 | `cores/hazard3/rtl` |
| Ibex | `cores/ibex/rtl` |
| VeeR EL2 | `cores/veer_el2/rtl` |
| riscv-tests | `common/bench/riscv-tests` |
| CoreMark | `common/bench/coremark` |

Vendor RTL is never edited. The changes we need are patch files in `cores/<core>/patches/`. The
flow applies them to a copy under `build/patched/`, and the reason for each patch is in
`docs/DECISIONS.md`.

## Rebuilding the results tables

Every number in `results/`, `reports/`, emails and the paper must come from `scripts/collect.py`
parsing a tool report. Don't type or copy numbers by hand (`CLAUDE.md`, "Numbers integrity").

The script uses only the Python standard library and reads the reports already committed under
`results/raw/`, so it runs on a fresh clone without any EDA tools:

```sh
scripts/collect.py              # rewrites results/results.csv, sim_results.csv, harden_results.csv,
                                #   fpga_results.csv
scripts/collect.py --md synth   # also print the synthesis table as Markdown
scripts/collect.py --md sim     # RTL sim: tests passed, CoreMark/MHz, DMIPS/MHz
scripts/collect.py --md harden  # core-only layout: fmax, DRC/LVS, slack, slew, area, power
scripts/collect.py --md fpga    # FPGA: timing, core utilization, power, board cycles
```

`make all-results` also regenerates the tables inside `reports/initial_synthesis.md` and
`reports/email_prof_draft.md`, then renders the PDF. The PDF step uses
`~/tools/venv/bin/python` and headless Chrome.

Running `collect.py` on an unchanged checkout should leave `git status` clean. If it doesn't,
something has changed under `results/raw/`.

## FPGA side (for Ayush)

Everything for the PYNQ board is in **`fpga/`**. Exact steps are in `fpga/README.md`:

- **One Vivado command per core:**
  `vivado -mode batch -source fpga/vivado/build.tcl -tclargs <core> 50`
- **A notebook** that runs all benchmarks on the board and checks the cycles against the RTL
  simulation.
- **Results:** copy them into `results/raw/fpga/` and run `scripts/collect.py --md fpga`.

The FPGA designs reuse the ASIC flow's wrappers, configurations, patches and benchmark images.
The only FPGA-specific change is how clock gating is mapped for Ibex and VeeR (same function,
same cycle counts). It's recorded in `docs/DECISIONS.md` (2026-11-18) and was approved by
Dwiti on 2026-11-18.

Still blank in `docs/PROJECT_FACTS.md`: the board (Z1 or Z2; same part, same bitstream), the
PYNQ image version, the Vivado machine and the Vivado version. Fill these in, and add Vivado to
`docs/VERSIONS.md`.

## Tools (ASIC/sim side)

Exact versions are in `docs/VERSIONS.md`.

- **ASIC tools**: all ASIC numbers come from the tools inside the pinned LibreLane 3.0.17
  container. They're run through `flows/librelane.sh`, so Docker is required.
- **Simulation and elaboration checks**: the host OSS CAD Suite.
- **Tool locations**: by default `flows/env.sh` expects OSS CAD Suite in `~/tools/oss-cad-suite`
  and the sky130A PDK under `~/.ciel`, installed with ciel. Override either from the shell.

Examples:

```sh
flows/sim.sh hazard3 coremark                      # RTL sim; log in results/raw/sim/hazard3_default/
make ibex-synth TECH=sky130 CLK=50                 # synthesis + pre-layout timing estimate
flows/run_layout.sh hazard3 30                     # core-only layout with the current flow settings
```

`make <core>-sim` and `make <core>-harden` are still placeholders in the Makefile. Use
`flows/sim.sh` and `flows/run_layout.sh` (or `flows/synth.sh` with `HARDEN=1`) directly.

## SCL 180 nm

The SCL PDK is under NDA and is **not** in this repo. Never commit PDK files or reports that quote
PDK internals. The rules are in `CLAUDE.md`, and access status is in `docs/PROJECT_FACTS.md`.
